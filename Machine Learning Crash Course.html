Warm-up · W.1

For machine learning, data is usually just a table

Eight students from last year. Press Next step to learn the names of each part.

Row = one example

Each row is one student. Also called a sample, record or data point. The number of rows is written n (here n = 8).

Columns = features

The facts we know about each student: hours studied, attendance, sleep. Also called inputs, attributes or x.

The answer column = label

"Passed?" is what we want to predict. Also called the target, output or y. Data with this column filled in is called labelled data.

The whole point

A new student arrives: 5 hours, 80% attendance, 7 hours sleep, but we don't know the result yet. A trained model looks at the patterns in the 8 rows above and makes a prediction for this new row.

Warm-up · W.2

Σ just means "add them all up"

Formulas in ML use the Greek letter Σ (capital sigma) a lot. It is a short way to write a long sum.

Try it
xᵢ

"the i-th value". x₁ is the first number, x₂ the second, and so on.

Σ xᵢ

Add every xᵢ: x₁ + x₂ + … + xₙ.

x̄ (x-bar)

The mean (average) = Σ xᵢ ÷ n.

You will also see

Σ xᵢyᵢ = multiply each pair, then add (used in linear regression, 2.1). Σ xᵢ² = square each, then add. Be careful: Σ xᵢ² is not the same as (Σ xᵢ)². For [1, 2, 3]: Σ xᵢ² = 1 + 4 + 9 = 14, but (Σ xᵢ)² = 6² = 36.

Warm-up · W.3

A straight line is the simplest model: y = m·x + b

Auto-rickshaw fare

Fare = ₹15 per km × distance + ₹30 starting charge. That is y = 15x + 30. m = 15 is the slope (how much y grows for each 1 step of x). b = 30 is the intercept (the value of y when x = 0).

Try it

Change m and the line gets steeper or flatter. Change b and the whole line moves up or down. Machine learning's job is to find m and b from data, when nobody tells us the fare chart.

Warm-up · W.4

Probability is just counting: how many out of how many?

100 days of weather in a village. Each square is one day. Click the buttons to count.

Count
rain
cloudy morning (thick border)
The bar | means "given that"

P(rain | cloudy) = "out of the cloudy days only, what fraction had rain?" We shrink the world to just the cloudy days and count again. This is called conditional probability.

Order matters

P(rain | cloudy) = 0.50 but P(cloudy | rain) = 0.75. They are different questions with different answers. Mixing them up is the mistake behind the medical-test surprise in Hour 1.4.

Warm-up · W.5

Distance between two points: Pythagoras from Class 8

Drag the pointsStarts at P(4, 5) and B(5, 4) from the KNN example in Hour 2.6
d = √( (x₂ − x₁)² + (y₂ − y₁)² )
Why ML cares

"Close together" means "similar". KNN (2.6) predicts using the closest examples; K-Means (3.3) groups points by distance. With more features, you just add more squared differences under the square root: √(Δx² + Δy² + Δz² + …). This is called Euclidean distance.

Another distance

Manhattan distance = |Δx| + |Δy|, like walking along city blocks instead of cutting diagonally. It is also shown in the panel above.

Hour 1 · 1.1

Writing rules by hand vs. letting the computer learn them

Traditional programming

Rules (written by you)+Data→Output

Machine learning

Data+Output (answers)→Rules (learned)
Be the spam filterTick words. An email is flagged as spam if it contains any ticked word.
Definition

Machine learning is building systems that get better at a task by learning patterns from data, instead of being programmed with explicit rules. Tom Mitchell (1997) made it precise: a program learns from experience E on a task T, measured by performance P, if P improves with E. Spam: T = sort emails, P = % sorted correctly, E = a pile of labelled emails.

Why now? Three things together

Data: phones and the internet produce huge amounts of it. Compute: cheap cloud computers and GPUs. Algorithms: better techniques, and free libraries like scikit-learn that anyone can use.

Hour 1 · 1.4

Mean tells you the centre; variance tells you the spread

Notes example · edit the numbers
Why square the distances?

Distances below the mean are negative and above are positive; they would cancel out to exactly 0. Squaring makes them all positive. Then the square root (standard deviation) brings the unit back: if the data is in marks, σ is in marks.

Divide by n or n − 1?

The notes divide by n ("population" variance), as sklearn's StandardScaler does. Many tools, including pandas .std() and Excel STDEV, divide by n − 1 ("sample" variance), which gives a slightly bigger number. For [10, 20, 30, 40, 50]: 14.14 with n, 15.81 with n − 1. Both are correct; they answer slightly different questions.

Hour 1 · 1.4 continued

A positive result from a "very accurate" test may still be probably wrong

10,000 people · each square is one person
sick, test positive (true positive)
sick, test negative (missed)
healthy, test positive (false alarm)
healthy, test negative

P(A | B) = P(B | A) · P(A) / P(B)
Why so low?

Only 100 of 10,000 people are sick, and 99 of them test positive. But 5% of the 9,900 healthy people also test positive: 495 false alarms. So of 594 positives, only 99 are truly sick: 99/594 ≈ 16.7%. Rare things produce many false alarms. This is why "accuracy" alone can fool you (Hour 2.8).

Small wording detail

The notes call this test "99% accurate". Strictly, it catches 99% of sick people but wrongly flags 5% of healthy ones, so out of all 10,000 people it is right about 95% of the time. Try a rarer disease and watch the true-positive share fall further.

Hour 1 · 1.5

Too simple misses the pattern. Too complex chases the noise.

A real experiment: we draw 200 different training sets of 13 noisy points from the same true curve, fit a polynomial to each, and look at all the fits together.

Experiment

Grey: 20 of the 200 fits. Teal: their average. Orange dashed: the true curve.

━ test error┅ train error━ bias²━ variance··· noise · x = degree · log scale

Total error = Bias² + Variance + Irreducible noise
Bias

How far the average fit is from the truth. High when the model is too simple: every training set gives roughly the same wrong curve. → underfitting

Variance

How much the fit changes from one training set to another. High when the model is too complex: it bends to follow each set's random noise. → overfitting

Irreducible noise

Randomness in the data itself (here σ = 0.3, so noise² = 0.09). No model can beat it.

Correction to the notes' sketch

The ASCII diagram in the notes labels bias as "train error" and variance as "test error". They are not the same thing. As complexity grows, bias² falls and variance rises; the test error is their sum plus noise, which is why it is U-shaped. The training error just keeps falling. The chart above shows all four correctly. The notes' table of numbers is a fine illustration of the same pattern.

Hour 2 · 2.1

Linear regression: find the line with the smallest squared errors

House size vs. price. Model: ŷ = m·x + b. Press Next step to solve m and b by hand with the least-squares formulas.

m = (nΣxy − ΣxΣy) / (nΣx² − (Σx)²)
b = (Σy − mΣx) / n
Try it · click the chart to add a house, right-click to remove
MSE: Mean Squared Error

MSE = (1/n) Σ (yᵢ − ŷᵢ)². The notes' bad guess, Price = 0.05 × Size + 2, has errors −2, −7, −12, −17 → squares 4, 49, 144, 289 → MSE = 486 / 4 = 121.5. The fitted line (0.04 × Size + 5) passes through every point: MSE = 0. Training means searching for the m and b with the smallest MSE.

Hour 2 · 2.3

Regularisation: charge the model a fee for big weights

Cost = MSE + λ × Penalty
Notes example · press Next stepw = [3, −2, 0.5], λ = 0.1, MSE = 10
See it work · a degree-9 polynomial on 15 points

The 9 weights (standardised features)

L1 (Lasso): Σ|wᵢ|

Pushes small, useless weights all the way to zero. The model automatically drops features: built-in feature selection.

L2 (Ridge): Σwᵢ²

Squaring hits big weights much harder (3 → 9), so it shrinks big weights smoothly, but rarely to exactly zero.

Extra details

λ is a hyperparameter: you choose it with cross-validation (1.7, 4.2). λ = 0 means no regularisation; huge λ squashes everything to a flat line (underfitting). Mixing L1 and L2 is called Elastic Net. Features should be scaled first (4.1), otherwise the penalty treats them unfairly.

Hour 2 · 2.4

Logistic regression: squash a line into a probability

z = w·x + b
σ(z) = 1 / (1 + e−z)
About e

e ≈ 2.718 is a special constant. e−z is always positive: big when z is very negative, tiny when z is very positive. So σ(z) is always between 0 and 1. Examples: e−0.8 = 0.449, e1.6 = 4.953.

Pass or fail from hours studied
Log loss (binary cross-entropy)
Cost = −[y·ln(ŷ) + (1 − y)·ln(1 − ŷ)]
Two things to remember

Despite its name, logistic regression is used for classification. The decision boundary is where σ(z) = 0.5, i.e. z = 0. With w = 0.8, b = −4: 0.8x − 4 = 0 → x = 5 hours. More than 5 hours → predict pass.

Hour 2 · 2.5

Decision trees: ask the yes/no question that best separates the classes

Gini impurity · notes example
Gini = 1 − Σ pᵢ²     Entropy = −Σ pᵢ log₂ pᵢ
A real tree on 2-D data

Subtle details

Trees split on one feature at a time, so their boundaries are made of straight horizontal and vertical pieces. They don't need feature scaling. An unlimited-depth tree keeps splitting until every leaf is pure, which memorises the data: limit max_depth or min_samples_leaf to control overfitting. Entropy for the parent node: −[0.6·log₂0.6 + 0.4·log₂0.4] = 0.97.

Hour 2 · 2.6

KNN: you are like your nearest neighbours

Notes example · drag P

What k does to the boundary · 160 points

Subtle details

KNN does no training: it stores the data and does all the work at prediction time, so it is slow on big datasets. It depends on distance, so features must be scaled (4.1). Use an odd k for two classes to avoid tied votes. In the notes example, A and D are both 2.83 away: a tie for 2nd place, but both fit inside k = 3.

Hour 2 · 2.7

SVM: the widest possible road between two classes

Try to beat the SVM

Margin = 2 / ‖w‖

The line is w·x + b = 0. The edges of the road are w·x + b = ±1. Notes example: w = (2, 0) → ‖w‖ = √(2² + 0²) = 2 → margin = 2 / 2 = 1. Making the margin wide = making ‖w‖ small. The points touching the road edges are the support vectors; only they decide the line.

Kernel trick in one picture

Extra detail

Real data overlaps, so SVMs allow some points inside the road for a penalty. The hyperparameter C sets how strict that is (big C = strict, narrow road; small C = relaxed, wider road). The popular RBF kernel lets SVM draw curved boundaries. SVMs need scaled features.

Hour 2 · 2.8

Confusion matrix, precision, recall, F1

Spam filter on 100 emails · 20 spam, 80 normal

Each dot is an email placed by the model's spam score. Top row: really spam. Bottom row: really normal. Everything right of the line is predicted spam.

Precision

"Of the emails I called spam, how many really were?" Matters when false alarms are costly: an important email lost in the spam folder.

Recall

"Of all the real spam, how much did I catch?" Matters when missing one is costly: cancer screening, fraud.

F1

The harmonic mean of the two: one balanced number. It is low if either one is low.

The accuracy trap

Press "Always say not spam": accuracy 80%, but it catches zero spam (recall 0). The same lesson as the medical test in 1.4: on imbalanced data, accuracy alone lies. Moving the threshold trades precision against recall; you cannot usually max both.

Hour 3 · 3.1

Many average trees beat one clever tree

Analogy

Ask one friend to guess the number of sweets in a jar and they may be way off. Ask 50 friends and average the guesses: individual mistakes cancel out. This is the "wisdom of the crowd", and it is why bagging reduces variance.

Step 1 · bootstrap: sample WITH replacement
Original dataset (10 rows)
Bootstrap sample (10 draws)

Some rows appear twice or more, others not at all. On average a bootstrap sample contains about 63.2% of the distinct rows. The left-out rows ("out-of-bag") can be used to test that tree for free.

Step 2 · vote (notes example) · click a tree to change its vote

For a number (regression) we average instead: (62 + 58 + 65 + 60 + 70) / 5 = 315 / 5 = 63 lakh
A real random forest vs. one deep tree
One fully grown tree
Random forest

Each forest tree is fully grown on its own bootstrap sample and, at every split, may only look at one randomly chosen feature (of the two). Background shade = share of trees voting teal.

Random forest = bagging + trees + random features

The extra trick: at each split a tree may only consider a random subset of features. That makes the trees more different from each other (less correlated), so their mistakes cancel better. In sklearn: max_features.

Hour 3 · 3.3

K-Means: assign to the nearest centre, move the centre, repeat

Notes example · press Next stepA(1,1) B(2,1) C(8,8) D(9,9), k = 2, start C1 = (1,1), C2 = (9,9)
Run it yourself · 150 unlabelled points

Elbow chart computed on these 150 points (best of 5 starts per k).

WCSS and the elbow

WCSS = sum of squared distances from each point to its own centre. More clusters always lowers it (k = n gives 0), so pick the elbow: where adding a cluster stops helping much. Notes table: 180, 60, 40, 35, 32 → elbow at k = 2 or 3.

Weaknesses

You must choose k. The result depends on the random start (press Random start a few times: sometimes it gets stuck in a worse answer), so sklearn runs several starts and uses the smart k-means++ starting points. It assumes roughly round clusters and needs scaled features.

Hour 3 · 3.4

Hierarchical clustering: keep merging the two closest groups

Press Next step to merge · then cut the tree

No k needed in advance

The dendrogram records every merge and the distance at which it happened. Cut it with a horizontal line at any height: the number of branches the line crosses is the number of clusters.

Details

"Distance between two groups" can be defined several ways: closest pair (single linkage, used here), farthest pair (complete), average, or Ward's method (sklearn's default). It compares every pair of points, so it gets slow beyond a few tens of thousands of points.

Hour 3 · 3.5

PCA: find the direction where the data spreads the most

Rotate the axis

The 1-D data you keep: every point projected onto the axis.

Notes example
Variance along x = 50, along y = 2. Keep only x: 50 / (50 + 2) = 50 / 52 = 96.2% of the total variance, with half the features.
The maths behind it, in one line

PC1 is the top eigenvector of the data's covariance matrix, and its eigenvalue is the variance along it. PC2 is at right angles to PC1, and so on. Always standardise features first, or a feature measured in big units (rupees) will dominate. In sklearn, explained_variance_ratio_ gives the "% kept" for each component.

Feature engineering: cleaning and shaping the data

Real data is messy. This step often matters more than which algorithm you pick.

Missing values · imputation
Text categories → numbers

Why scaling matters · a KNN with two features

Notes example · [10, 20, 30, 40, 50]
min = 10, max = 50, mean μ = 30, std σ = √((400 + 100 + 0 + 100 + 400)/5) = √200 = 14.14
Min-max of 20: (20 − 10) / (50 − 10) = 10 / 40 = 0.25  → range [0, 1]
Standardise 20: (20 − 30) / 14.14 = −10 / 14.14 ≈ −0.71  → mean 0, std 1
Who needs scaling?

Needs it: KNN, SVM, K-Means, PCA, anything trained by gradient descent, regularised models. Doesn't care: decision trees, random forests, gradient-boosted trees (they only compare values within one feature). Use the median for skewed data like income, where a few huge values drag the mean.

Hour 4 · 4.3

The whole course in 35 lines of scikit-learn

Iris: 150 flowers, 3 species, 4 measurements each (sepal and petal length and width). Click any line.

Three things to know about this code
  • Scaling does nothing for a random forest. Trees only compare values within one feature, so StandardScaler is harmless but unnecessary here. It is shown because you would need it for KNN, SVM or logistic regression.
  • A small leak inside cross-validation. The scaler is fit on all of X_train before GridSearchCV splits it into folds, so each validation fold was seen by the scaler. The clean fix is a Pipeline: make_pipeline(StandardScaler(), RandomForestClassifier()), so scaling is re-fit inside every fold.
  • Expect a very high score. Iris is easy: the test set is only 30 flowers, and accuracy is usually around 0.9 to 1.0. One flower = 3.3%, so don't read too much into small differences.

Hour 4 · 4.4

Four ways to fool yourself

1 · Data leakage

2 · Imbalanced data

1% disease (1.4: only 16.7% of positives were real) and 20% spam (2.8: "always not spam" scores 80% accuracy with zero spam caught). Fixes: use precision, recall and F1; give the rare class more weight (class_weight="balanced"); oversample it (e.g. SMOTE).

3 · Overfitting the test set

If you check the test score, change something, check again… the test set has secretly become a validation set and the final number is too optimistic. Tune with validation data or cross-validation; open the test set once.

4 · Garbage in, garbage out

No algorithm fixes wrong, biased or meaningless data. A loan model trained on past decisions copies past unfairness. Time spent understanding the data usually beats time spent trying fancier models.

Bonus · the world changes

A model trained before a new UPI scam appeared won't recognise it. Monitor models after deployment and retrain (1.3, box 9).
